## 它是怎么工作的

在你的项目文件夹里启动 Claude Code 之后,你用自然语言告诉它要做什么。它会:

1. **读**项目里相关的文件,弄清楚现状;
2. **想**一个做法;
3. **改**文件、运行命令;
4. **报告**它做了什么。

你不需要自己指出每个文件在哪,它会自己去找。

## 先理解"权限"

因为它能改文件、跑命令,所以它在做有影响的操作之前会**先问你**。你可以在"每次都问"和"更放手"之间选择权限模式。

我的建议是:

- 刚开始用,选**每次都问**,这样你能看清它在做什么;
- 熟悉之后,再对**只读的、安全的**操作放行;
- 涉及删除、发布、对外发送内容的操作,**始终自己确认**。

## 几个最常用的操作

- **提及文件。** 在对话里用 `@` 指定文件,让它重点看那里。
- **先出方案,再动手。** 复杂任务先让它给计划,你确认后再执行(计划模式就是为此设计的)。
- **看改了什么。** 改完后看 diff,确认只改了该改的地方。
- **管理上下文。** 对话变长时,可以用 `/compact` 压缩,用 `/context` 看占用情况。
- **用 `/init` 生成项目说明。** 它会扫描项目,生成一份 `CLAUDE.md`(下一章细讲)。

## 一次典型的使用

1. 进入项目文件夹,启动 Claude Code。
2. 描述任务,并说明背景和约束(参考上一章)。
3. 让它先说方案,确认。
4. 让它动手,过程中留意它请求的权限。
5. 跑测试、看 diff,确认没问题后再提交。

## 小结

把 Claude Code 当成一个**能干活、但需要你把关**的搭档。你的价值在于说清需求和检查结果,而不是亲自敲每一行。
