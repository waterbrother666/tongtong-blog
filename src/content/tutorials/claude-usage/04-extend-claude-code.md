## 为什么要扩展

开箱的 Claude Code 对你的项目一无所知。每次开新对话,你都得重新交代一遍规矩,很累。扩展的作用,就是**把交代一次的东西固定下来**。

## CLAUDE.md:项目的说明书

`CLAUDE.md` 是放在项目里的一份文本文件,每次启动都会被读进去。适合写:

- 怎么运行、怎么测试;
- 代码风格和命名约定;
- **不要做的事**(比如"不要直接改数据库迁移文件");
- 目录结构和重要的设计决定。

写法上有两个原则:

1. **短而具体。** 写得越长,越容易被忽略。
2. **写它猜不到的东西。** 目录结构它自己能看,但"为什么这样设计"它猜不出来。

## Skills:可复用的做事方法

Skill 是一包"怎么做某类事情"的说明,需要时才会被加载。适合把**重复出现的流程**固定下来,比如:

- "部署到某个平台的步骤";
- "按我们团队的标准做代码评审";
- "写周报的格式和口吻"。

和 `CLAUDE.md` 的区别:`CLAUDE.md` 是**每次都要知道**的规矩,Skill 是**用到时才加载**的专项方法,不占日常的上下文。

## MCP:接入外部工具和数据

MCP 是一种让 Claude 连接外部服务的方式,比如浏览器、数据库、设计工具或内部系统。接入之后,它就能直接使用这些工具,而不只是读你的文件。

使用时要记住两点:

- **只接你需要的。** 每多一个工具,上下文就多一份开销,也多一份风险。
- **注意权限和数据。** 它能访问什么,就可能泄露什么;敏感系统要特别谨慎。

## 三者怎么选

| 想解决的问题 | 用什么 |
| --- | --- |
| 每次都要重复交代项目规矩 | `CLAUDE.md` |
| 有一套固定流程想复用 | Skill |
| 需要它操作外部工具或读外部数据 | MCP |

## 小结

扩展的目标不是堆功能,而是**让重复交代的事情只说一次**。先写好一份精炼的 `CLAUDE.md`,再按需添加 Skill 和 MCP。
